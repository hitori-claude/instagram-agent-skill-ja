# ig-human（AIっぽさ消し）

このフォルダの2つのツールは、実際に動きます。目で見て判断せず、ツールを回します。

```bash
python humanize.py draft.txt --report        # 直して、何を変えたかを見る
python detect.py draft.txt                    # 5項目で採点する
python detect.py before.txt after.txt         # 直す前と後を比べる
```

どちらも `slop.json` を読みます。中身は次のとおりです。

- AIの日本語によく出る定型句 168個（置き換え先つき。一部は「数えるだけ」）
- 見えない文字 18種類
- 記号の置き換え 9種類
- AIっぽい文の型 18種類

この辞書は自分用に育てるものです。自分の口ぐせが入っていて消されたくないなら、
その行を消してください。

## インスタで特に効く理由

キャプションは短く、台本は声に出して読まれます。600字のキャプションに1行だけ
硬い文があると、長い記事より目立ちます。声に出しにくい台本は、撮る前の1回目で
つまずきます。怖いのは判定ツールではありません。読む人が「広告っぽい」と感じて
スクロールしてしまうことです。

## 自動で直すもの

**1. 見えない文字。** ゼロ幅スペース、ソフトハイフン、BOM、タグ文字など。
キーボードからは打てない文字で、コピペしても残ります。全部消します。
全角スペースは日本語で普通に使うので残します。

**2. Markdown記号。** `**太字**`、`# 見出し`、`- 箇条書き`、`` `コード` ``、
`[文字](URL)`、`> 引用`、`---`。インスタには反映されず、記号がそのまま出ます。
記号だけ外します。箇条書きは「・」にします。`#ハッシュタグ` は残します。

**3. 記号。** ダッシュ（— ― –）は文脈で変えます。

- 「です」「ます」などの言い切りのあと → 「。」
- 短い挟み込み（A—B—C）→ 「A（B）C」
- 数字の範囲（5–10）→ 「5〜10」
- それ以外 → 「、」

“ ” は「 」にします。数字や「！」「？」で全角と半角が混ざっていたら、多いほうにそろえます。

**4. 定型句。** 置き換えても意味が変わりにくいものだけ直します。例です。

- 「いかがでしたか？」→ 削除
- 「〜と言えるでしょう」→「〜と思います」
- 「〜することが重要です」→「〜するのが大事です」
- 「さまざまな」→「いろんな」
- 「〜において」→「〜で」
- 「まさに」→ 削除
- 「させていただきます」→「します」

URLの中は触りません。

## 自動では直さないもの

次の2つは報告だけします。文の形を変えるには判断がいるからです。

**数えるだけの定型句。** 「〜ではないでしょうか」「結論から言うと」「魅力」「革命的」
「紐解く」「寄り添う」など。言い換えると意味が変わりやすいので、レポートに出すだけにしています。

**文の型。**

- 「AだけでなくBも」「Aではなく、Bなのです」
- 「ポイントは3つ」「A、B、そしてC」
- 「〜していきましょう！」
- 「〜の世界へようこそ」「こんなお悩みありませんか？」
- 「今回は〜をご紹介します」のような前置き
- 体言止めが3行以上続く
- 読点（、）が4つ以上ある長い一文
- ✅ や 📌 で始まる絵文字の箇条書き
- ハッシュタグ10個以上
- 「フォローしてね」「保存して見返してね」の反射的なお願い

ここはあなたの仕事です。意味を残したまま1行ずつ書き直して、もう一度 `detect.py` を回します。
REVIEW を PASS に動かすのはこの部分で、スクリプトにはできません。

## 5つのチェック

`detect.py` は5項目を 0〜100 で採点します。高いほど人間らしいです。

| 項目 | 見ているもの | AIっぽいとき |
| --- | --- | --- |
| 文の長さ | 文の長さのばらつき（文字数） | どの文も同じくらいの長さ |
| 語尾 | です・ます止めの割合、同じ語尾の連続、話し言葉っぽい文末 | 「です。ます。です。」が続く。「ね」「よ」「笑」がない |
| 定型句 | 1000字あたりの定型句の数と、文の型の数 | 決まり文句が多い |
| 記号の痕跡 | 見えない文字、ダッシュ、Markdown記号、全角半角の混在 | 手打ちでは出ない記号がある |
| 硬さ | 漢字の割合、一文あたりの読点、体言止めの連続 | 漢字が多く、読点で長くつないでいる |

全体の点は「平均×60%＋いちばん低い項目×40%」です。1つの特徴だけで疑われるので、
弱い項目を重く見ています。PASS は全体70以上、かつ全項目55以上です。

## 正直に伝えること

これは手元で動く簡易チェックです。文章はどこにも送りません。
GPTZero などの判定サービスではなく、その判定を約束するものでもありません。

しきい値と辞書は、経験則で決めた仮のものです。日本語の文章データで検証はしていません。
英語版の検証結果もそのまま日本語には当てはまりません。点数は「直す場所の目印」として使い、
「これで判定ツールにバレない」とは言わないでください。

短いキャプション（4文未満や60字未満）は、一部の項目が「判定できません」になり50点で計算されます。
丁寧語で書く人は「語尾」の点が低めに出やすいです。

## 進め方

1. `python humanize.py draft.txt -o clean.txt --report`
2. レポートの5と6（自動で直していない所）を読んで、自分で書き直す
3. `python detect.py draft.txt clean.txt` で前後を比べる
4. PASS でなければ、出力に出る「いちばん弱い項目」から直してもう一度。
   2回で済むのが普通です。5回かかるなら、型で書かれた下書きです。直すより書き直したほうが早いです。
5. ユーザーには直した文章と点数を一緒に見せます。点数だけは見せません。
